## 八条验收逐项实测

### 1. 浮窗能开 —— ✅ 通过

- 双击 `启动.cmd` 后无边框浮窗出现（自绘蓝色标题栏，半透明 85%），截图确认全部控件
  （亮度滑块/外观/强调色/任务栏/壁纸/一键还原/高级折叠区）渲染正常。
- 拖动：模拟鼠标从标题栏拖 200×150，`GetWindowRect` 实测 1520,80 → 1720,230，**DRAG OK**。
- 位置记忆：托盘路径不易自动化，改用 `WM_QUERYENDSESSION` 触发正常退出（等效系统关机路径），
  退出后 `%APPDATA%\WinCtlPanel\ui.json` 内容：
  ```json
  { "x": 1720, "y": 230, "w": 396, "h": 640, "topmost": false }
  ```
  重新启动后 `GetWindowRect` 返回 **1720,230（与记录一致）**。保存、加载两个半程均实测通过。
- 托盘图标：UIA 在「系统托盘溢出窗口」中找到名为 "WinCtlPanel 控制面板" 的图标 ✓。

### 2. 亮度能调 —— ✅ 通过

- 浮窗滑块从 30% 拖到约 74%，随即用原工具交叉验证：
  ```
  PS> brightness.ps1 -Get
  显示器[0] Generic PnP Monitor  亮度 74%  (原始 74, 范围 0-100)
  ```
- 备份文件同时记录原值：`"bright:0": "0;30;100"`。
- 还原后复测：`亮度 30% (原始 30, 范围 0-100)` ✅。
- 防抖：实现为 200ms Timer，拖动中仅更新数字，松手（MouseUp）立即下发。

### 3. 深色能切 —— ✅ 通过

- 点「深色」后注册表：`AppsUseLightTheme=0 SystemUsesLightTheme=0`；
- **开始菜单立刻变深色**（截图为证，无需重启/注销），浮窗按钮高亮 + 状态栏反馈
  「已切换到深色模式（应用/开始菜单立刻生效）」。

### 4. 强调色能改 —— ⚠️ 部分通过（注册表链路全通，任务栏颜色本机不跟随）

- 点色块后注册表：`AccentColor=4287070979`（= 0xFFB86487，即预设紫 #8764B8），
  **ABGR 顺序转换正确**（另有 SelfTest 三个纯色转换用例全过）；`ColorPrevalence` 0→1。
- 还原链路单独验证：把 AccentColor 改成纯红 0xFF0000FF 后点「一键还原」，
  `AccentColor=4281550495`（原值）✅。
- **降级点**：任务栏/开始菜单背景颜色在本机不跟随新强调色——依次试了
  `ImmersiveColorSet` 广播、同时写 `AccentPalette`（32 字节）、重启资源管理器，
  任务栏像素始终不变（约 RGB 30,57,121）。该机装有 Wallpaper Engine 且任务栏为
  系统材质色，判断是系统/第三方接管了任务栏配色，不是本工具写值失败。
- 若需彻底换任务栏颜色，本机建议仍走 Wallpaper Engine。

### 7. 一键还原 —— ✅ 通过（修复一处 bug 后）

- 覆盖项实测：亮度 74%→30% ✅、壁纸→原 jpg ✅、TaskbarAl ✅、AppsUseLightTheme
  深→浅 ✅、AccentColor 红→原值 ✅、ColorPrevalence 1→0 ✅、`backup.json` 删除 ✅。
- 启动时残留备份提示弹窗逻辑在代码中，未单独触发实测（需要留下未还原改动再启动）。
- **测试中修掉的 bug**：备份 JSON 里的 AccentColor 原值 4281550495 超过 Int32，
  `ConvertFrom-Json` 解析为 Int64，`[int]` 强转溢出抛异常被吞，导致该项不还原。
  已加 `ConvertTo-RegInt`（Int64→补码 Int32）修复，并单独实测 accent 还原路径。

### 8. 失败提示 —— ✅ 通过

- DDC 不支持路径：SelfTest 用零句柄调 `GetMonitorBrightness` 返回 null，
  UI 层据此显示「显示器[N] …：设置失败。你的显示器可能不支持 DDC/CI，或在显示器菜单里
  关闭了它。」（滑块对不支持的屏直接禁用并显示"不支持"）。
- 锁屏需要管理员：点「设置锁屏图片…」弹确认框（截图为证）：
  > 锁屏图片走的是组策略键（HKLM），需要管理员权限。点「确定」后会弹出 UAC 提升窗口，
  > 请手动确认。还原方法：删除 HKLM\...\LockScreenImage / LockScreenImageStatus。
  点「取消」即中止，全程未写 HKLM ✅。
- 重启资源管理器：确认框实测弹出、可取消 ✅。
- 真实拔显示器场景未做（无法模拟），由 DDC 失败路径 + 禁用滑块兜底。

## 附：测试中踩过的坑（对以后改这个工具有用）

1. PowerShell 5.1 里 `New-Object Point(18, $y + 6)` 的逗号优先级高于 `+`，
   会被解析成 3 个参数——构造函数第二个参数是表达式时必须加括号。
2. 所有含中文的 .ps1 必须 UTF-8 with BOM，包括临时辅助脚本（本次多个辅助脚本栽在这）。
3. 本机 `Add-Type` 内联 C# 必须显式 `using System;`，否则 UIntPtr/IntPtr 找不到。
4. UIA 的 BoundingRectangle 是物理像素，而非 DPI-aware 进程的 SetCursorPos 用逻辑
   坐标，换算要 ÷2（200% DPI）；WinForms 控件句柄在 Visible=false 时未创建，
   枚举子窗口前要先展开折叠面板。
5. SendMessage(BM_CLICK) 到会弹 MessageBox 的按钮会阻塞到对话框关闭，自动化时
   要用独立进程处理弹窗。
