# kbdprobe · 键盘延迟探针

把「键盘迟滞 / 粘滞」的主观感觉变成**可复现的量化数据**：分位数 + 异常计数 + 系统侧快照。
Windows 专用，单文件 `kbdprobe.py`，**仅 Python 标准库**（ctypes），无需管理员，不联网，不写注册表，不改键位。

---

## 〇、隐私红线（先读这个）

**绝不记录按键内容、字符、键名、窗口标题、输入法候选。**

只允许存在四类数据：VK 虚拟键码（纯数字，如 65）、时间戳、事件类型（down/repeat/up）、派生指标（按住时长/相邻间隔/处理延迟）。

自审方法（应零命中）：

```bash
grep -nE "GetKeyNameText|ToUnicode|ToAscii|MapVirtualKey|GetWindowText|GetClipboard|OpenClipboard" kbdprobe.py
```

注意：VK 序列 + 时间戳理论上仍可推断输入节奏，日志只留在本机 `samples\`，**不要外发**。

---

## 一、快速开始

```powershell
# 方式一：一键（采 60 秒 → 出报告 → 打开输出目录）
powershell -ExecutionPolicy Bypass -File run_sampling.ps1

# 方式二：直接跑（采 60 秒）
python kbdprobe.py --seconds 60

# 方式三：采到 Ctrl+C 为止
python kbdprobe.py

# 自测（合成数据，不碰真实键盘，不写文件）
python kbdprobe.py --selftest
```

采样期间**正常打字 / 游戏**；想测「粘滞」就刻意长按几个键。到点自动停止并生成两个文件：

| 文件 | 内容 |
|---|---|
| `samples\kbdprobe_<时间戳>.csv` | 每条按键事件的原始记录（几十 KB 级） |
| `samples\kbdprobe_<时间戳>_report.txt` | 文本报告（分位数 + 异常计数 + 结论） |

崩溃保护：采样中途每 5 秒把已采数据写进 `*.csv.tmp`，异常退出（断电/被杀）也不丢；残留的 `.tmp` 就是最后落点，可直接读。

## 二、CSV 数据字典

```
t_ns,sys_event_ms,vk,kind,hold_ms,gap_ms,proc_ms
234629318331400,234629296,100,down,,,0.000
234629378998500,234629343,100,up,60.667,60.667,7.824
```

| 列 | 含义 |
|---|---|
| `t_ns` | 本进程打点时刻（`perf_counter_ns` 单调钟，纳秒） |
| `sys_event_ms` | 系统给事件打的戳（`KBDLLHOOKSTRUCT.time`，GetTickCount 时基，**粒度 ~15.6ms**） |
| `vk` | 虚拟键码**数字**（65=某字母键；IME 组合键统一是 229；不含任何键名） |
| `kind` | `down`=按下 / `repeat`=同键未抬起的自动重复 / `up`=抬起 |
| `hold_ms` | 按住时长（up 行回填；会话开始前就按着的键无配对，留空） |
| `gap_ms` | 与上一条事件的间隔（ms） |
| `proc_ms` | 处理延迟 = 系统时间戳→本进程处理完（ms；**含 ±8ms 时钟粒度噪声**，负值钳 0） |

## 三、指标定义与判读方法（核心）

### 3.1 健康参考带（经验值，非硬标准）

| 指标 | 健康范围 | 说明 |
|---|---|---|
| `hold_ms` p50 | 60–150ms | 正常打字单键按住时长 |
| `gap_ms` p50 | 80–300ms | 打字节奏因人而异，**绝对值不重要，看异常计数** |
| `proc_ms` p50 | ≤10ms | 含 ±8ms 时钟噪声，**0~10ms 的值一律当「无延迟」看** |
| `proc_ms` p95 | ≤20ms | 超过 → 钩子排队/系统忙 |
| `sched_ms` p95 | ≤10ms | Python≥3.11 的基线噪声 ~2–6ms；超 15ms → 系统负载/省电 |

### 3.2 判读步骤（拿到报告后按顺序走）

**第 1 步 · 看结论行**（报告底部）：

- `处理延迟>200ms: 有` → **迟滞的机器证据**（系统收到按键后隔了 >200ms 才轮到我们处理）。
- `异常按住(>300ms 且无自动重复伴随): 有` → **粘滞的机器证据**（详见 3.3）。
- 两个都是「无」→ 跳第 3 步。

**第 2 步 · 有证据时，定位时段**：`>200ms 卡顿点` 和 `proc>200ms` 的明细都带时间戳（HH:MM:SS.mmm）和 VK 数字。对照卡顿点发生的时刻，回忆当时在干什么（游戏团战 / 后台在装更新 / 什么都没干）。

**第 3 步 · 区分「人停顿」和「机器卡」**——这是判读最容易翻车的地方：

- `gap>200ms` 只说明**两次事件隔了 200ms**，可能纯粹是你在走神。
- 判据：**同一时刻 proc 是否也高**。proc 高 → 机器真卡（系统侧排队）；proc 正常 → 人停顿，忽略。
- 一个 60s 会话出现 1~3 个卡顿点**通常毫无意义**；密集出现（每分钟 >10 个）且 proc 同步升高才是问题。

**第 4 步 · 结合系统快照**（报告底部 JSON）：

- `dpc_pct` 持续 >10% → 驱动/中断问题（见排查树 3）。
- `cpu_busy_pct` >80% 且当时没在重负载 → 后台任务抢资源。
- `usb_selective_suspend.value = 1`（启用）→ 延迟敏感设备建议改禁用对比（控制面板 → 电源选项 → 高级设置 → USB 设置）。
- `power_plan` 是省电类计划 → 换高性能再采一次对比。

### 3.3 「粘滞」为什么看「无自动重复伴随」

Windows 对按住的键会持续发自动重复（repeat，间隔 ~30ms，首次延迟 ~250–500ms）。所以：

- 按住 700ms **且 repeat 跟上了** → 正常长按（游戏移动键、退格清行）。
- 按住 >300ms **但 repeat 一次都没来、up 又迟到** → 说明 up/repeat 在系统侧排队/丢了才送过来 → 这才是「粘滞」的机器证据。

报告里两者分开计数：`含故意长按共 N 次`（参考）与 `无自动重复伴随 M 次`（判粘滞看这个）。

### 3.4 复现纪律（避免单次偶然）

- 同一姿势连采 **3 次 × 60s**，对比三次的 p95 与异常计数，趋势一致才算数。
- 采样时段保持环境一致：别一边装系统更新一边采；电源设置不要中途改。
- 怀疑「最近变卡」：先采一次现状，把本目录留着，隔几天再采对比。

## 四、排查树（按证据指向下一步查什么）

1. **proc 高 + sched 高** → 系统负载侧：电源计划改高性能；查后台（杀毒扫描 / Windows 更新 / 云同步）；笔记本查省电模式。
2. **粘滞（异常按住）多** → 键盘厂商软件（G HUB / Synapse 等的宏、过滤、节电功能，先全部关掉再采）；USB 选择性暂停改禁用；**换 USB 口**（主板后置直连，别走 hub / 前面板 / 键盘线延长）；换线。
3. **DPC% 持续 >10%** → 驱动层：跑 LatencyMon 定位具体驱动；重点排查 USB3 控制器驱动、网卡 / 声卡驱动。
4. **队列长度高 + CPU 忙** → 后台抢核；采样时关掉重负载程序再对比。
5. **所有指标正常但手感仍差** → 硬件本身：换一把键盘交叉验证；或把本键盘插到另一台机器跑同一探针对比（探针是单文件，U 盘就能带走）。

## 五、已知限制

- **测不到键盘内部延迟**：LL 钩子的起点是「系统已收到事件」，键盘主控 / 线缆 / 接口物理层的那段延迟不在本探针范围内（那属于硬件域，探针正常 ≠ 硬件没问题）。
- 本探针自身开销（消息泵 + Python 回调，亚毫秒~几毫秒）计入 proc，属系统性底噪。
- proc 含 GetTickCount 粒度噪声（±8ms）：**10ms 级的差异不要当结论**，只看 >50ms / >200ms 的量级。
- `sys_event_ms` 列粒度 ~15.6ms，两个相邻事件可能共用同一时间戳，属正常。
- `sched_ms` 噪声基线取决于 Python 版本：3.11+ 用高精度等待（~2–6ms）；更老版本 ~15ms 粒度。
- 注入键也会被记录（SendInput / 远程桌面 / 按键宏软件）；采样期间别开按键宏。
- **安全软件可能拦 LL 钩子**：现象 = 安装失败（报 `GetLastError=5/875` 等）或事件数恒为 0。替代方案是 Raw Input（`RegisterRawInputDevices` + `RIDEV_INPUTSINK`，不进钩子链、消息直投窗口，能拿到同结构事件流）——本工具未实现，需要时可按此思路扩展 `--raw-input` 模式。
- 对比采样时保持电源设置一致：省电模式 / USB 节电会让所有指标系统性偏高。

## 六、实现要点（给要改代码的人）

- 钩子：`SetWindowsHookExW(WH_KEYBOARD_LL)`，回调**一律** `CallNextHookEx` 原样放行（连异常路径也是——放行写在 try 外，打点失败绝不拦截按键）。`CallNextHookEx` 的 argtypes 必须显式钉死，否则 64 位 `l_param` 高位为 1 时 ctypes 抛 OverflowError → 回调返回 0 → **静默拦截按键**（红线，已修，别回退）。
- 时基：`KBDLLHOOKSTRUCT.time` 是 GetTickCount 时基（粒度 15.6ms），采样前用 24 个样本把两钟对齐（取中位数 offset），proc_ms 才有意义。
- 统计与采样解耦：`derive()` / `analyze()` 是纯函数，`--selftest` 用同一套代码跑合成序列断言 39 项。
- 原子落盘：临时文件 + `os.replace`；中途每 5s 重写 `.tmp`。
- 阈值集中在文件顶部常量区（`STALL_GAP_MS` / `STICKY_HOLD_MS` / `PROC_LAG_MS`），改阈值 = 改判读标准，改完必须跑 `--selftest`。
