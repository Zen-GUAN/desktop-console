# 任务书：面板布局适配（窗口尺寸自由化）

> 2026-11-07 · 下达方：ZCode（后端） · 执行方：Kimi（前端，CSS 为主）
> 背景：后端已支持**窗口尺寸/位置记忆**——用户可以把窗口拉成任意大小，关闭重开原样保持（800ms 防抖落盘 `%APPDATA%\WinCtlPanel2\ui.json`）。因此 UI 必须在 340×480 到超大窗口之间都体面。用户实机反馈的两个问题如下，只改 CSS（如需结构微调只加类名不改逻辑）。

## 用户实机问题

1. **小高度窗口**：底部「更多工具 / LOCAL OFFLINE」贴死下边缘（无呼吸空间），内容超高时被裁切且无法滚动到底。
2. **大宽度窗口**：卡片被拉满全宽，内容稀疏难看（用户称「全屏的 UI 太空了」）。

## 需求

1. **高度自适应**：`.content` 允许 `overflow-y: auto`；底栏（statusbar / under-actions）保证固定下边距（≥12px 视觉呼吸）；窗口再矮文字也不被裁切、能滚到底。
2. **宽度自适应**：主体列设 `max-width`（建议 460px 左右，自行微调）并水平居中；大窗口下卡片不无限拉宽，两侧留白可用现有 ambient/渐变维持氛围。
3. 默认 380×600 的观感**不得劣化**（这是主形态）。
4. 深浅两主题都过；devtools 无 CSP 告警；零外链资源。

## 禁止事项

- 不改交互逻辑与后端契约（窗口尺寸记忆已由后端完成，前端无需做任何尺寸 UI）
- 不引入外部资源；不动 token/安全逻辑；中文引号「」

### 8.1 代码改动

仅修改 `v2-web\ui\style.css`，未改 HTML、JavaScript、后端契约或安全逻辑：

1. `.app-shell` 的 `min-height` 从 `480px` 改为 `0`，避免矮视口把外壳撑出可视区域；`.content` 继续使用 `flex: 1; min-height: 0; overflow-y: auto`。
2. `.content` 的底部 padding 从 `8px` 增至 `12px`，保证滚动到底后「更多工具 / LOCAL OFFLINE」仍有呼吸空间。
3. `.content > *` 增加 `width: 100%; max-width: 460px; margin-left/right: auto`，让六个主体区块在大窗口中居中限宽，小窗口仍铺满原有可用宽度。
4. `.statusbar` 增加 `margin-bottom: 12px` 和 `flex: none`，状态栏不再贴死窗口下边缘，也不会被 flex 压缩。
